# Real Point-of-Care Queries (Real-POCQi)

**Real-POCQi** is a blinded, specialty-matched benchmark of real-world clinical decision support queries submitted by practicing U.S. physicians to the [OpenEvidence](https://openevidence.com) platform, paired with answers from four AI systems and pairwise ratings by physician specialists.

## Dataset Overview

| | |
|---|---|
| Questions | 620 |
| Medical specialties | 30 |
| AI systems evaluated | 4 |
| Answers | 2,480 (4 per question) |
| Pairwise comparisons | 1,156 |
| Rating rows | 5,780 (5 axes × 1,156 comparisons) |
| Physician raters | 149 |
| U.S. states covered | 36 |

## Provider Keys

| Key in data | System |
|---|---|
| `openevidence` | OpenEvidence (specialized clinical tool) |

| `gemini-3.1-pro` | Gemini 3.1 Pro |
| `gpt-5.5` | GPT-5.5 |

## Study Design

Real-POCQi contains 620 queries submitted by physicians relating to point-of-care clinical decisions through the OpenEvidence (OE) platform, spanning a total of 30 medical specialties. Queries were drawn from questions submitted between June 7–14, 2026, filtered for PHI and non-clinical content, and lightly rewritten to remove identifiable details.

Answers to the clinical queries were provided, as generated by Gemini 3.1 Pro, GPT-5.5, Claude Opus 4.8, and OpenEvidence.

149 practicing U.S. physicians were asked to conduct blinded pairwise comparisons between LLM answers to the clinical queries with respect to five dimensions: Accuracy, Clinical Utility, Source Quality, Completeness, and Verifiability. Surveys were rendered where answers were displayed to contain only text from the LLM answers (text-only render mode) or contain both text and citations (text+citation render mode). The survey platform also randomized the order in which LLM answers were shown. Physician graders were matched to answer only questions generated by an OE user registered with the same specialty.

For full methodology, see the [accompanying paper](https://arxiv.org/pdf/2606.28960).

## Schema

### `questions` (620 rows)

| Column | Type | Description |
|---|---|---|
| `question_id` | string | UUID, primary key |
| `question_text` | string | Rewritten clinical query |
| `specialty` | string | Medical specialty (e.g., `Cardiology`) |

### `answers` (2,480 rows)

| Column | Type | Description |
|---|---|---|
| `question_id` | string | Foreign key → questions |
| `provider_key` | string | AI system identifier (see table above) |
| `answer_markdown` | string | Full answer in Markdown |

### `ratings` (5,780 rows)

Each pairwise comparison (1,156 total) generates 5 rows — one per evaluation axis.

| Column | Type | Description |
|---|---|---|
| `question_id` | string | Foreign key → questions |
| `axis` | string | Evaluation dimension (see below) |
| `choice` | string | Physician preference (see below) |
| `slot_a_provider` | string | AI system shown as Answer A |
| `slot_b_provider` | string | AI system shown as Answer B |
| `render_mode` | string | Survey render mode: `qa_text_only` or `qa_text_citations` |

**Evaluation axes**

| `axis` | Question posed to raters |
|---|---|
| `accuracy` | Which response is more factually accurate? |
| `clinical_utility` | Which response is more useful for providing high-quality clinical care? |
| `source_quality` | Which response is supported by more authoritative source material? |
| `verifiability` | Which answer is easier to verify? |
| `completeness` | Which response more completely addresses the question? |

**Rating scale**

| `choice` | Meaning |
|---|---|
| `strongly_a` | Answer A is much better |
| `slightly_a` | Answer A is somewhat better |
| `tie` | About equal |
| `slightly_b` | Answer B is somewhat better |
| `strongly_b` | Answer B is much better |
